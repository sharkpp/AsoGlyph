## 決定事項

- **書き替えるのは `text` だけ。`reading` には手を入れない。** 読みは読み上げ専用で
  ひらがなに揃える決まり（SPEC 7.4.2）なので、ことばの字づかいを変えても変わらない
- **単語帳の `name` / `author` / `description` も通す。** 名前には
  「でんしゃのなまえ（カタカナ）」のように中身を言いあてた字が入っており、
  まとめて直すと意味がずれる
- `[かっこ]`（SPEC 7.4.0）の中は直す。1 語のなかで字づかいが揺れないようにする
- **出力は別ファイル**（`asodict_rename_words.py` の上書きとは違う）。字づかいを
  変えたぶんは元の冊と並べて置くもの。入力と同じ名前を渡せば上書きになる
- **ひらがなで書けなくなる語は名前を挙げる。** ひらがなに「ー」は無い（SPEC 5。
  カタカナ 81 字にだけ入っている）ので、`hira`／`swap` では出題から外れる語ができる。
  判定は「ひらがなが混じっているのに `ーヷヸヹヺ` が残っている語」
- 漢字・ラテン・数字・空白はそのまま通す（かなに開くのは `asodict_rename_words.py` の仕事）
- 対応する字: ぁ〜ゖ ↔ ァ〜ヶ（0x60 のずれ）＋ ゝゞ ↔ ヽヾ（ずれが違うので別の表）
- 行ごとに `text:` 行だけを差し替える方式（`asodict_rename_words.py` と同じ）。
  YAML を組み直さないので、コメントと知らないキーが落ちない
- 読めないファイルは日本語で理由を言う（`単語帳ファイル（.asodict）ではありません`）

## 捨てた選択肢と理由

- **読みをことばから起こし直す**（`asodict_rename_words.py` はそうしている）…
  採らない。読みは元からひらがなで、字づかいを変えても変わらない。起こし直すと
  漢字の残る語（「深海怪獣」）で手で書いた読みが消え、`]` が空白に替わって
  手で整えた読みも変わる
- **`.yaml` やフォルダも受ける**（`asodict2pdf.py` はそうしている）… 採らない。
  要求は `.asodict`。兄弟の `asodict_<何を>.py` の約束（README の名前の付け方）に従う
- **入力を上書きする**（`asodict_rename_words.py` と同じ）… 採らない。ひらがな版と
  カタカナ版は対で置くもの（`train_names_*.yaml`）で、元の冊が消えると片方しか残らない
- **`--swap` に既定値を持たせる**… 採らない。黙って何かが変わるより、毎回書かせる
- **`・`（U+30FB）も「書けない字」として挙げる**… 採らない。カタカナのブロックに
  入っているが、名前の区切りに使われていて挙げると雑音になる。落とすのは置き換えの表の仕事

## ハマりどころ

- zsh で `echo =====` が `=` の展開に当たって落ちる。区切りを出すときは避ける
- `dart run <scratchpad>/check.dart` は `package:asoglyph/...` を解決できない。
  パッケージの中（`work/` など）に置いて走らせる必要がある
- python に `yaml` が入っていないので、出力の検証はアプリ側の
  `parseWordBookBundle`（Dart）で行った。こちらのほうが本番と同じ経路で確かめられる

## 学び

- `_ウルトラヒーロー.asodict` の読みは元から `うるとらまん てお` のようにひらがな。
  `]` が空白に替わる規則（`word_text.reading_of`）が実データに乗っている
- `kana` を掛けても直る語はごく少ない（ウルトラヒーローで 58 語中 2 語）。
  カタカナの単語帳はすでにカタカナで書かれている
- 「ー」がひらがな 80 字に無いことは SPEC 5 と `train_names_hiragana.yaml` の
  コメントの両方に書かれている。ひらがなの単語帳を作るときの制約として効く
