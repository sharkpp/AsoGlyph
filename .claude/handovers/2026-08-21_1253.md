## 決定事項

- **なぞりの下敷きを消すかは人ごと。切り替えは管理画面に置く。** 子供向け画面は
  タップだけで完結させるところで、書くまでの手数を増やす選択肢を足さない
- **フォントの出口は管理画面だけ。** 版の一覧からも版の画面からも出せる。
  子供向け画面には置かない
- **おまかせは戻るまで語が出続ける。** やめるのは書く人の側で決める
- **1 字もどるの印は、取り消し（1 画もどす）と共有しない。** 消えるのが
  片方は 1 画、こちらは 1 字ぶんで、取り返しのつく範囲が違う
- **iOS の選ぶ画面は識別子（UTI）しか見ない。** 独自の拡張子は Info.plist で宣言し、
  Dart 側の識別子と揃える（テストで縛った）
- **web の書き出しは Blob の URL。** `navigator.share` には渡さない
- **書き出し・読み込みの失敗は必ず画面に出す。** 黙ると、控えを取ったつもりのまま端末が壊れる
- **内蔵の辞書は資産 1 つに 1 冊。寄せるときは誰かに割り振られている側を残す**

## 捨てた選択肢と理由

- **練習モードを 3 つの印としてヘッダに並べる**（`_ModeBar`、`AppBar.bottom`）… 一度入れたが
  ユーザーの指示で撤回。「おうちの人へ」と同じ並びのメニュー 1 つにした
- **1 字もどるを Undo の印にする** … 採らない。隣の取り消しと同じ印が 2 つ並ぶ。
  ユーザーの判断で「Undo 以外の分かりやすい印」にした
- **`PracticeMode` と `traceErases` を 1 つの値オブジェクトにまとめる** … 採らない。
  引数 1 つ増やすだけで足りる（AGENTS.md の「いちばん簡単な実装」）
- **単語帳の絵が読めないときの空き枠を直す** … 今回は触っていない。報告は
  「絵が無い語の下の空き」で、原因は枠の `minHeight` の上寄せだった
- **内蔵辞書の id を資産パスから決める（決定的な id）** … 採らない。既存端末の
  `User.wordBooks` の割り振りが外れる。source で寄せるほうで足りる
- **寄せるときに割り振り（`User.wordBooks`）を id ごと書き換える** … 採らない。
  ストアをまたぐ仕掛けが増える。`preferred` で残す側を選べば実害はほぼない
- **plist に私たちが送らない mime を名乗る**（`application/x-asoglyph-backup` の
  mime タグ）… 落とした。iOS は拡張子で種類を決める。zip の mime を名乗ると
  ほかの zip まで自分の種類として拾ってしまう

## ハマりどころ

- **`flutter analyze` は info でも終了コード 1**。出力を `grep -E "error|warning"` で
  絞ったせいで `use_build_context_synchronously` を見落とし、CI（`pages.yml` の
  `- run: flutter analyze`）を落とした。**絞らず全文を見る**
- `git checkout <file>` で、コミット前の Info.plist の編集を丸ごと失った。
  テストで壊れることを確かめる用途なら、書き戻す前提で必ず控えを取る
- 内蔵辞書の重複は **リロードでは再現しなかった**。試して外したもの:
  リロードのみ / DB を二重に開く（ホットリスタート・2 タブ）/ 同期の途中で閉じる /
  絵入り `.asodict`。**別の置き場の控えから戻す**ところで再現した
- `flutter test --platform chrome` は `TestWidgetsFlutterBinding.ensureInitialized()`
  が要る。実資産（`AssetManifest`）の読み込みはブラウザのテストでは固まるので、
  `FakeBundledAssets` を使う
- 語の書き取りテストは実時間が要る（`tapDone` / `advance` / `waitFor`）。
  `Future.delayed` の決め打ちでは足りない

## 学び

- iOS の選ぶ画面は `extensions` を見ない。`file_selector_ios` は
  `uniformTypeIdentifiers` が空だとその場で投げる（押しても何も起きない形になる）
- iOS Safari は共有できるファイルの種類を絞り、大きい data: URI も受け付けない。
  share_plus の web フォールバックはそこで必ず失敗する
- 内蔵の辞書の id が端末ごとだと、控えのやり取りで重複する。iPad は
  Safari とホーム画面のアプリで置き場が別（SPEC 10.1）なので、1 台でも踏む
- 直す前の状態でテストを走らせて落ちることを確かめると、そのテストが何を
  守っているかがはっきりする（枠の空き・plist の食い違いで実施）
