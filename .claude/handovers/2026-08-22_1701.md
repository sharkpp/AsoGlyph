## 決定事項

- **選ばせるときの絞り込みは web では効かせない。** 「選べない」より「選んでから断る」。
  読めなければ何が悪いかを言う
- **iOS は識別子・Android とデスクトップは拡張子で今までどおり絞る。** web だけ外す
- **URL から取ってくるのは単語帳だけ。** こちらから何も送らない（SPEC 3 は保つ）
- **拡張子の無い URL も受ける。** 配る側は `?id=...` で渡すことがある。zip の頭が
  見えたら絵ごとの単語帳、`csv` と言ってきたら CSV、どちらでもなければ YAML
- **取り込みの入口は 2 つ（ファイル・URL）でも、通る道は 1 つ**（store の import）

## 捨てた選択肢と理由

- **`mimeTypes` を足して web でも絞る** … 端末の中のファイルは拡張子から種類を
  推される。`.asodict` は推されないので、足しても Safari では灰色のまま
- **Safari だけを見分けて分ける** … ブラウザの見分けは当てにならないし、
  絞れてもうれしいのは「ほかのファイルが薄く見える」だけ
- **控え（`.asoglyph`）の絞り込みも web で外す** … いまは選べている。触らない
- **URL の取り込みに独自の HTTP を書く** … `http` は公式で、web でも端末でも同じ道。
  依存を 1 つ足すほうが安い
- **落とす大きさに上限を置く** … ファイルからの取り込みにも上限は無い。
  絵は 1 枚 512 KB で切ってあるので、そこは変わらない

## ハマりどころ

- **ディスクが満杯で `flutter test` が固まった。** エラーではなく「テスト実行器が
  0% CPU で居座る」形になるので、ハングに見える。`--reporter expanded` で
  流し直して初めて `No space left on device` が出た
  - 直前の数字: データボリューム 426Gi/460Gi、空き 320MB。`flutter test` は
    一時ファイル（`flutter_tools.*/`）に 1 回 60〜70MB 使い、**1GB を切ると危ない**
  - 止まった実行の一時ディレクトリは残る。消してよい（実行中でないことを確かめてから）
- **`&` で始めた実行は、そのツール呼び出しが返ると死ぬ。** 途中までのログが残るので
  「そこで止まった」と読み違える。長い実行は `run_in_background` を使う
- Safari の `accept` の振る舞いは「直せた種類だけに絞る／全部直せなければ絞らない」。
  **一部だけ直せるときがいちばん悪い**（残ったものしか選べない）

## 学び

- 「動いている」ことと「正しく動いている」ことは別。控えの取り込みが動いていたのは
  拡張子が 1 つで、それが**全部落ちたから**。**偶然動いているものは、隣で 1 つ足すと壊れる**
- 同じ後始末（絵の付け替え）が UI と store の両方にあると、入口が増えるたびに写しが
  増える。入口は増やしてよいが、**通る道は 1 つに寄せる**
- 端末の許し（`INTERNET`）は debug と profile に自動で足されるので、**手元では
  気づけない**。release にしか出ない不具合になる
