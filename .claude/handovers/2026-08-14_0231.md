## 決定事項

- **TTF ライタの自作は成立した。SPEC 8.2 の最大リスクは解消。**
- 内部表現は 3 次ベジェで統一。TTF 出力時のみ 2 次へ落とす（OTF は無損失）
- 巻き方向の内部規約は **TrueType 準拠（外周が時計回り）**。CFF 出力時に全輪郭を反転する
- loca は常に long 形式（オフセットが 2 で割れる制約を持ち込まない）
- name テーブルは Windows プラットフォーム（3,1,0x409）のみ。家族名に子供の名前など
  非 ASCII が入りうるため Mac Roman レコードは持たない
- CFF の文字列は ASCII に落とす。真の名前は name テーブルが持つ
- CFF の Top DICT のオフセットは 5 バイト固定長（op 29）で書き、確定後に同じ長さで差し替える
- post は version 3.0（グリフ名を持たない）
- `FontMetadata.created` を呼び出し側から与える設計にした。生成を純関数に保ち、
  FontRecipe から同じフォントを再現できるようにするため
- fontTools はプロジェクトの依存にしない。検証時にだけ venv へ入れる

## 捨てた選択肢と理由

- **fontify の流用（OTF）** — 結局 CFF を自前で書いた。TTF を自作する以上、共通テーブルと
  sfnt コンテナは自前で持つことになり、CFF だけ外部に頼る利点が無かった。依存も減る
- **glyf のフラグ REPEAT 圧縮** — 実装せず。ファイルサイズの利得より可読性を優先。
  必要になってから入れればよい
- **CFF の標準文字列（SID 0..390）の利用** — 使わず、必要な文字列をすべて自前登録した。
  標準文字列表への依存を持ち込まないため
- **cmap format 12** — 対象文字がすべて BMP に収まるため format 4 のみ

## ハマりどころ

- **近似誤差テストが 1.54 で落ちた（実装ではなくテストの誤り）**
  2 次曲線を「点の集合」として最近傍距離を取っていたため、サンプル間隔（約 1.25）が
  誤差に上乗せされていた。折れ線の**線分**までの距離で測るよう修正して解決
- **fontTools 検証で円の面積が 0.1% 合わないと報告された（これもしきい値の誤り）**
  - OTF: 真円比 -0.019%。円を 3 次ベジェ 4 本で近似する古典的手法（k=0.5523）の
    固有誤差そのもので、実装の問題ではない
  - TTF: -0.109%。差分から逆算した半径方向のずれは約 0.156 単位で、許容誤差 0.5 の内側
  - しきい値を `2*pi*r*0.5 / 面積` という根拠のある値に置き換えた
- `DateTime` は const にできないため `FontMetadata` の const コンストラクタを諦めた

## 学び

- **glyf の座標は整数**。したがって 3 次→2 次の許容誤差を 0.5 未満に下げても意味がない。
  丸めの量子化誤差が下限になる。tolerance = 0.5 が自然な設定
- TrueType と CFF は**外周の巻き方向の慣習が逆**（TrueType=時計回り、CFF=反時計回り）。
  どちらも nonzero winding なので単一輪郭では見た目に出ないが、穴あきグリフで効く
- fontTools の `AreaPen` で符号付き面積を取ると、巻き方向と穴あきの正しさを一度に検証できる。
  座標・曲線変換・輪郭の向きをまとめて確かめられる良い検査
- `TTFont.save()` での再保存が通るかどうかが、テーブル整合性の実用的な検査になる
