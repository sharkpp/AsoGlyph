## 決定事項

- **保存は sembast。** 純 Dart で web（IndexedDB）まで 1 実装で通る。
  筆跡は端末内で完結させる方針（SPEC 3）に沿う
- **運筆は詰めたバイナリで保存する。** メタデータ（char / mode / writtenAt）は
  `samples` ストア、運筆は `strokes` ストアに Blob で分けた。
  一覧と充足率の表示に必要なのは書いた事実だけで、全文字ぶんの運筆を
  メモリへ載せる理由がない。運筆を読むのはフォント生成のときだけ
- **id は UUID v7。** 先頭に時刻を持つため、id 順がそのまま書いた順になる。
  同一ミリ秒の記録でも `SortOrder('writtenAt')` + `SortOrder(Field.key)` で順序が一意に決まる
- **「できた！」を押した時点で必ず記録する。** 字の巧拙で採否を決めないのが製品の中核
  （SPEC 1）。子供に「これでいい？」と判断させる導線は作らない
- **なぞり書きは進捗には数え、素材には採らない。** `attemptCount` は全モード、
  `latestMaterialId` は `mode.isFontMaterial` のみを見る
- **`userId` / `score` / `wordAttemptId` / `rejected` は今は持たない。** それぞれ L3 / L4 の話。
  一方 `mode` は今入れた。素材採用の可否がこれで決まるため、後から足すと
  既存レコードの補正が要る（AGENTS.md の「移行レイヤを作らない」に反する）
- **フォント出力は収集画面へ移した。** L1 では書き取り画面にあったが、
  出口は「集めた字全体」に対して開くもの

## 捨てた選択肢と理由

- **運筆を JSON で保存**（sembast のマップにそのまま入れる）… 数倍に膨らむ。
  web の IndexedDB では容量がそのまま効く。SPEC 4.1 が 7 バイト/点を明示している
- **`hive_ce` / `drift`** … sembast で足りる。drift は L2 の要求に対して重い
- **全 Sample をメモリに載せる** … 今は動くが SPEC 4.5 の試算（8 MB）で破綻する。
  最初からメタデータと運筆を分けておけば、後で困らない
- **`uuid` を使わず自前の時刻付き id** … 6 行で済むが、established なライブラリを
  優先する方針（AGENTS.md）に従った。v7 なら時刻順も得られる

## ハマりどころ

- **`testWidgets` の中で sembast を直接 await すると永久に止まる。**
  ウィジェットテストは疑似非同期環境で、sembast の使うタイマが進まない。
  `flutter test` が 5 分以上返ってこず、`tail` でバッファされて症状が見えなかった。
  → 記録の読み書きは `tester.runAsync` の中で行う。
  ラスタ化・輪郭化だけのテストは `testWidgets` をやめて素の `test` にした
  （`TestWidgetsFlutterBinding.ensureInitialized()` があれば `Picture.toImage()` は動く）
- **`_tapDone` の 500 ms 決め打ちが不安定だった。** 単体では通るのに、他のテストと
  一緒に走らせると記録が 0 件になる。ラスタ化が 500 ms に収まらないと
  その後の保存まで到達しない。→ 字形が出るまで実時間でポーリングする形に変えた
- `flutter test 2>&1 | tail -40` は全部バッファされるため、ハングの切り分けに使えない。
  `--reporter compact` を素で流すこと

## 学び

- ウィジェットテストの疑似非同期は、`Future` を返すだけのライブラリなら透過するが、
  内部で `Timer` を使うものは止まる。sembast はこれに当たる
- 待ち時間の決め打ちは、単体では通って結合で落ちる。結果そのものを待つこと
